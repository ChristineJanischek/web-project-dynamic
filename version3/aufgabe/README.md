# Version 3: Webpräsenz für eine nachhaltige Schülerfirma

## 🎯 Projekt-Briefing

Du entwickelst die Webseite für **MiFa - Mission Future Academy**, eine neu gegründete Schülerfirma, die sich auf nachhaltige Software im Bereich Bildung und Ökologie spezialisiert.

**Mission von MiFa:**  
"Wir entwickeln digitale Lösungen, die Bildung fördern und die Umwelt schützen - von Schüler:innen für die Zukunft."

---

## 📋 Aufgabenstellung

### Phasen-Übersicht

Diese Version ist in **zwei Hauptphasen** unterteilt:

#### **Phase 1: Konzeption & Design (60%)**  
Planung und Gestaltung der Webseite

**Ergebnisse am Ende von Phase 1:**
- Finaler **Firmenname** (über Survey)
- Finaler **App‑Name** für die Mitfahrgelegenheits‑App (über Survey)
- **Corporate Design Guide** (Farben, Typografie, Logo‑Usage, Bildsprache)
- **Wireframes** für Start, Projekte, Services, Kontakt
- **Content‑Strategie** (Texte, Bildkonzept)

Siehe `phase1-concept/AUFGABEN.md` für eine Schritt‑für‑Schritt Anleitung.

#### **Phase 2: Technische Umsetzung (40%)**  
Programmierung mit HTML, CSS und JavaScript

In dieser Phase setzt ihr euer Konzept um:
- **Hintergrundgrafiken** (Hero, Sektionen) aus eurem Bildkonzept
- **Grafiken & Projektbilder** (selbst erstellt/optimiert)
- **Team‑Bildergalerie** mit 4–6 Mitgliedern
- **Corporate Design** (Farben/Schriften) konsequent in CSS umgesetzt

Starterfiles: `phase2-implementation/index-starter.html`, `css/style-starter.css`, `js/script-starter.js`

## Phase 1: Konzeption & Design

### Teil 1.1: Analyse & Zielgruppen (90 Min)

📖 **Theorie:**  
- [`docs/zielgruppenanalyse.md`](../../docs/konzeption/zielgruppenanalyse.md)  
- [`docs/konzeption-webdesign.md`](../../docs/konzeption/konzeption-webdesign.md)

**Lernziele:**
- Zielgruppen der Schülerfirma identifizieren
- Personas erstellen
- Nutzerbedürfnisse verstehen

**Aufgaben:**

1. **Zielgruppenanalyse durchführen**
   - Identifiziere mindestens 3 Zielgruppen für MiFa
   - Erstelle für jede Zielgruppe eine Persona (nutze das Template aus `zielgruppenanalyse.md`)
   - Definiere die wichtigsten Bedürfnisse und Ziele jeder Persona

2. **User Stories formulieren**
   - Schreibe mindestens 5 User Stories im Format:  
     *"Als [Nutzer] möchte ich [Funktion], um [Ziel] zu erreichen."*
   - Priorisiere die User Stories nach Wichtigkeit

3. **Customer Journey skizzieren**
   - Zeichne die Journey einer Persona von der ersten Wahrnehmung bis zur Kontaktaufnahme
   - Identifiziere wichtige Touchpoints

**Abgabe:**
- Dokument mit Personas (inkl. Fotos/Skizzen)
- Liste mit User Stories
- Customer Journey Skizze

### Teil 1.2: Corporate Design entwickeln (120 Min)

📖 **Theorie:**  
- [`docs/corporate-design.md`](../../docs/konzeption/corporate-design.md)

**Lernziele:**
- Corporate Design-Elemente verstehen
- Farbpsychologie anwenden
- Konsistentes visuelles Erscheinungsbild entwickeln

**Aufgaben:**

1. **Farbpalette definieren**
   - Wähle eine Primärfarbe, die Nachhaltigkeit und Innovation vermittelt
   - Definiere Sekundär- und Akzentfarben
   - Begründe deine Farbwahl mit Farbpsychologie
   - Dokumentiere alle Farben mit HEX-Codes

2. **Typografie festlegen**
   - Wähle 2 Schriftarten:
     - Eine für Headlines (z.B. aus Google Fonts)
     - Eine für Fließtext
   - Definiere Schriftgrößen-System (Überschriften, Text, Buttons)
   - Teste die Lesbarkeit

3. **Logo-Integration planen**
   - Analysiere das vorhandene Logo (`images/Logo_farbig.jpg`)
   - Definiere Verwendungsregeln (Größen, Platzierung, Schutzraum)
   - Erstelle Varianten (farbig, einfarbig für verschiedene Hintergründe)

4. **Bildsprache definieren**
   - Analysiere die vorhandenen Bilder im `images/` Ordner
   - Definiere Kriterien für weitere Bilder (Stil, Farben, Motive)
   - Erstelle Beispiele oder Referenzen

**Abgabe:**
- Style Guide Dokument mit:
  - Farbpalette mit Begründung
  - Typografie-System
  - Logo-Verwendungsregeln
  - Bildsprache-Guidelines

## 🔍 Phase 2 Checklisten

### HTML Struktur
- [ ] `<!DOCTYPE html>` & `lang="de"`
- [ ] Semantische Bereiche (`header`, `main`, `section`, `footer`)
- [ ] Sinnvolle Überschrift-Hierarchie (nur ein `h1`)
- [ ] Alt-Texte für alle relevanten Bilder
- [ ] Formulare mit Labels verknüpft

### CSS & Design
- [ ] Alle Farben und Fonts über Variablen (`:root`) gesteuert
- [ ] Konsistente Abstände (Spacing-Skala statt Zufallswerte)
- [ ] Keine redundanten Duplikate (DRY Prinzip)
- [ ] Fokus-Styles sichtbar
- [ ] Genug Kontrast (WCAG: Text-Kontrast > 4.5:1)

### Responsive
- [ ] Layout funktioniert bei 320px, 768px, 1024px, 1400px
- [ ] Navigation mobil → Hamburger-Menü
- [ ] Bilder skalieren ohne Verzerrung (`object-fit: cover`/`contain`)
- [ ] Keine horizontale Scrollbar
- [ ] Touch-Ziele groß genug (> 44px Höhe)

### JavaScript
- [ ] Navigation Toggle funktioniert (Öffnen/Schließen)
- [ ] Formular-Validierung verhindert fehlerhafte Eingaben
- [ ] Fehlermeldungen klar verständlich
- [ ] Keine Console-Errors
- [ ] Optional: Scroll-/Fade-In Effekte

### Bilder & Medien
- [ ] Richtige Formate (Fotos: JPG, Grafiken: PNG/SVG, Logos: SVG/JPG)
- [ ] Dateigrößen optimiert (< 300KB für Hero, < 150KB für reguläre Bilder)
- [ ] Lazy Loading für nicht-sichtbare Bilder
- [ ] Keine verzerrten Bilder (korrekte Aspect Ratios)
- [ ] Favicon eingebunden

### Accessibility
- [ ] `tab` Navigation möglich
- [ ] Skip-Link vorhanden (falls implementiert)
- [ ] ARIA nur wo nötig verwendet
- [ ] Form-Fehler mit `role="alert"`
- [ ] Keine rein farbcodierten Informationen

### Performance
- [ ] Keine unnötigen großen Bibliotheken
- [ ] Bilder komprimiert (ggf. TinyPNG, Squoosh)
- [ ] CSS & JS ohne tote Code-Blöcke
- [ ] Konsolen-Performance: keine Warnungen

### Finaler Pre-Release Test
- [ ] Seite lädt unter 3s (lokal, frischer Cache)
- [ ] Lighthouse (Performance > 70, Accessibility > 80)
- [ ] Validierung: HTML & CSS ohne kritische Fehler
- [ ] Deploy-Test (GitHub Pages möglich?)

## 🧪 Validierung von `names.json`
Während Phase 1 entsteht die Datei `phase1-concept/results/names.json` mit Firmen- und App-Namen.

Manuelle Prüfung lokal:
```bash
python3 scripts/validate_names.py
```
Ergebnis-Typen:
- ✅ Struktur valide – alle Pflichtfelder vorhanden
- ⚠️ Begründung sehr kurz – erweitere `entscheidung_begruendung`
- ❌ Schlüssel fehlt: firma – Feld ergänzen / korrigieren

Automatische CI:
- Workflow `Validate Names Artifact` läuft bei Änderungen an `names.json` (Push / Pull Request)
- Fehlermeldungen müssen vor Merge behoben werden
- Warnungen sind Hinweise zur Qualitätsverbesserung

Erwartete Struktur:
```json
{
   "firma": "MiFa",
   "alternativen_firma": ["FutureLab", "EduEco"],
   "app_mitfahr": "MiFaRide",
   "alternativen_app": ["EduRide", "GreenLift"],
   "entscheidung_begruendung": "Wir haben MiFa gewählt, weil …"
}
```

Ziel: Nachvollziehbare, geprüfte Namenswahl vor Start der technischen Umsetzung.

## ♿🗲 Qualität: Accessibility & Performance
Wir prüfen Barrierefreiheit (pa11y) und grundlegende Performance (Lighthouse) automatisiert.

### Lokal ausführen
```bash
# Accessibility Audit
npx pa11y file://$PWD/version3/aufgabe/phase2-implementation/index-starter.html --reporter cli
# Lighthouse (Einzel-Run)
npx lhci autorun
```

### CI Workflows
- `Quality Checks` Workflow läuft bei Änderungen an HTML/CSS/JS in `phase2-implementation/`.
- Accessibility-Ergebnisse: Hinweise zur Verbesserung (Build bricht nicht bei Warnungen).
- Lighthouse Assertions (siehe `.lighthouserc.json`):
  - Accessibility Score ≥ 0.80 (Fehler bei Unterschreitung)
  - Performance, Best Practices, SEO mit Mindest-Schwellen (Warnungen)

### Typische Verbesserungen
- Kontrast erhöhen (`color` / `background-color` anpassen)
- Fokus-Styles hinzufügen (`:focus-visible`)
- Semantische Überschriftenhierarchie sicherstellen
- Bilder mit `width`/`height` + optimierter Dateigröße
- Reduzierte CSS/JS (kein toter Code)

### Strukturdateien
- `.lighthouserc.json` steuert Scores & Upload
- `scripts/run_accessibility.sh` schneller pa11y Shortcut

Ziel: Frühzeitig Probleme erkennen statt am Ende improvisieren.
